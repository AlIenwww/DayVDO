## 实现

- 总待办与日历复用筛选状态、按钮和面板；两页各自保留会话中的选择。日历筛选由 `ContentView` 持有，没有写入偏好或数据文件。
- 月视图、周视图顶部待办、日期详情和关联安排使用同一匹配规则。关联安排按待办属性匹配，不依赖待办的日期是否属于当前周；独立安排保留。
- 明确选择状态时覆盖全局完成项设置。逾期以实际今天判断，原有待办日期保持不变。
- 缓存、预热与预计算日期布局纳入筛选条件；仅逾期条件纳入今天。切换条件取消旧请求，旧结果不会回写。跨日、重新激活及项目／标签删除会刷新对应条件。
- 修改筛选保持视图身份、日期、滚动及时间缩放；取消未提交拖动、清除隐藏选择。创建草稿走独立的预览布局，保存后按正式条件匹配。
- 修正共享匹配规则中“无项目／无标签”提前返回的问题，后续类别继续取交集。

### 侧栏恢复 Apple 原生行为（2026-10-02）

用户澄清只想理解窗口已激活时为何侧栏有时仍显示灰色，并要求遵循 Apple 官方行为。上一节强制纯色背景、白字及自定义焦点／方向键的实现已全部撤回。恢复 `List(selection:)` 与 `NavigationLink(value:)`，使用系统 `.sidebar` 样式；不覆盖选中背景、选中文字、强调状态、图标渲染或顶部淡化效果。星期栏的透明修正保留。

Apple 区分窗口的活动状态与窗口内部的第一响应者。`NSTableRowView.isEmphasized` 决定强调或次要选中颜色；`NSWindow.firstResponder` 通常是由鼠标或键盘激活的具体控件。窗口已激活时，焦点仍可在搜索框、正文或其他控件，侧栏灰色表示保留当前选择而未强调，不能仅凭窗口已激活认定异常。参考 [Apple isEmphasized](https://developer.apple.com/documentation/appkit/nstablerowview/isemphasized) 和 [Apple firstResponder](https://developer.apple.com/documentation/appkit/nswindow/firstresponder)。此前某一次变色没有第一响应者记录，不能断言其具体触发原因。

隔离包已恢复原生列表，实际看到活动窗口中总待办／日历仍保留灰色选中背景、蓝色图标及主文字色，切页及月历显示正常。界面工具随后再次报告 Mac 锁定，未继续追踪各控件之间的焦点迁移；该限制不作为灰色属于错误的证据。

完整 **165/165 测试通过**、Release 构建及 `git diff --check` 通过。日志为 `/tmp/dayvdo-062-native-sidebar-tests.log`、`/tmp/dayvdo-062-native-sidebar-release.log`。未提交、推送或修改正式数据。
