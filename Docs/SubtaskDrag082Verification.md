# 0.8.2 子任务拖动优化

2026-10-26。针对总待办项目内子任务的悬停换位。保留系统拖动预览、0.32 秒轻微回弹、减少动态效果分支，以及松手后一次保存和撤销。

## 改动

- 拖动状态移入当前项目的 `ProjectTaskList`，避免每次换位更新整个总待办页面。
- 任务行按稳定 ID 保持结构；悬停使用位置偏移，松手再提交持久化顺序。未变化行复用内容，首尾圆角随预览位置更新。
- 缓存行测量结果；内容版本、可见 ID、宽度、语言、字号和日期变化会重新测量。实际行高度改变时取消旧预览，避免使用过期偏移。
- 使用所属显示器的刷新回调合并悬停输入；退出目标取消待处理输入，松手处理最终目标后提交，取消丢弃预览。
- 使用列表坐标中的指针位移判断方向，过滤动画移动目标产生的重复进入；相邻任务可以直接反向换位。列表滚动也会改变该坐标，避免原地停留时阻断边缘滚动换位。
- 版本显示和本地打包脚本同步到 0.8.2。打包脚本属于仓库现有忽略目录。

## 性能对照

基线取本次修改前工作区源码（0.8.1），保存在 `/tmp/dayvdo-subtask-082-baseline`；优化版在 `/tmp/dayvdo-subtask-082-optimized`。两份临时副本仅加测试输入入口，生产源码不含入口。基线的鼠标松开轮询在该合成负载中停用，以免没有真实按键的测试被取消；优化版同样不启动轮询。

Release 原生窗口 800 × 600，20 / 200 个子任务，混合有无备注的不同高度。每组五轮，每轮连续向下、向上共 19 个悬停输入。构建结束后先运行基线五轮，再运行优化版五轮，没有并发编译或另一个性能测试。输入入口使用生产预览逻辑，优化版显式刷新队列以比较一次换位的工作量；因此不是对显示回调调度延迟的测量。

每次记录包含输入处理和四次布局/显示等待；CPU 为进程用户态与内核态时间增量。**不是单帧耗时、FPS、输入到屏幕延迟或完整系统拖动手感。** 连续动画和测试等待会影响 wall time。

| --- | --- | --- | --- |
| 20 | 更新区间耗时 | 65.77 / 70.97 | 65.85 / 75.14 |

## 验证与边界

最终 Debug 完整回归：307 项，304 项通过、3 项可选性能负载按设计跳过、0 失败。当前工作区最终源码 Release 构建通过。新增窗口检查也确认：提交真实顺序后保持预览最终位置，增加备注后重新测量行高。原始回归和构建日志已归档到上述 Performance 目录。

新增检查覆盖：静止指针和动画诱发目标变化不重复发布；直接反向换位；筛选时隐藏子任务顺序；不同高度行偏移；悬停不保存；松手一次提交与撤销重做；帧合并与取消；真实显示回调；原生拖放区域的位置移动和取消恢复。既有 200 行反复滚动及末尾目标可达性检查通过。

独立测试 App 的实际截图确认文字、备注、灰色边框和不同高度行显示正常；点击完成后图标、删除线、项目计数即时更新。Computer Use 拖动多次返回 `noWindowsAvailable`，一次未产生有效换位，未作为真实拖动通过证据。测试中的 `cacheDisplay` 截图只捕获了底层背景，已弃用，不能证明动态文字绘制。原生视图坐标断言证明布局与拖放目标位置，不能替代真实触控板逐帧体验验证。

建议实际验收：上下连续穿过多个子任务；停留于行边缘；立即反向；拖到末尾；Esc 取消；筛选后拖动；松手后切页返回并撤销。应看到连续让位、原地不抖动、最终顺序保存和取消恢复。特别关注大项目及边缘滚动；本轮未宣称这部分人工手感验收完成。
