# 0.8.0 日历性能优化验证

日期：2026-10-20。改动保留在当前工作区，未提交或推送。此次以周视图为重点，未改变用户数据格式。

## 结果与边界

同一台 Mac、同一 Release 配置、同一 1080×720 点窗口及相同合成数据，周视图重建、横向滚动和下方时间线竖向滚动的更新开销均降低。单位为 ms，表中进入列是三次重建的中位数，滚动列是脚本更新的 p95。

| 待办数 | 周视图重建：之前 → 之后 | 横向更新 p95：之前 → 之后 | 时间线竖向更新 p95：之前 → 之后 |
| ---: | ---: | ---: | ---: |
| 100 | 245.0 → 94.3 | 17.3 → 10.9 | 25.7 → 14.5 |
| 1,000 | 1227.2 → 271.6 | 83.7 → 20.2 | 154.5 → 22.5 |

1,000 条样本中，上方待办区最终竖向更新 p95 为 **69.7 ms**，位置检查通过。对照版在相同操作中回跳到 -64 点，无法保持目标滚动位置，因此没有可比较的旧版待办区耗时。此次同时修复了该滚动反馈问题，不能把无效的位置样本当作性能提升百分比。

压力场景仍有峰值：1,000 条横向单次最大更新为 104.8 ms，上方待办区为 92.7 ms。这轮结果不表示所有负载都已达到显示器刷新率。

这些数值是原生窗口中脚本驱动滚动后的布局／显示更新工作量，**不是物理显示器 FPS、触控板逐帧采样或从点击侧栏到屏幕首帧的延迟**。重建测量使用已准备好的数据缓存；不覆盖应用冷启动或完整侧栏切页链路。不能直接与旧报告中不同方法的首屏指标比较。

## 修改及体验约束

- 将周时间线的缩放／分钟位置和待办区的滚动位置分别放入观察模型，使高频位置变化停留在相关视口。移除它们经页面根状态传播的更新路径。
- 相邻周按实际可见范围创建，周边界变化只切换受影响周的活动状态；数据、筛选、语言、外观、选择、缩放或布局变化仍刷新对应内容。拖动起点所属视图离开屏幕后仍保留至手势结束。
- 周数据准备覆盖前后三周，共 49 天；只在邻近范围不足时补齐，保留旧快照直到新数据准备好。月视图缓存／滚动策略沿用原有行为。
- 周待办卡片只创建可见行及相邻缓冲行，选中项和拖动／新建预览持续保留。横向位置和命中区域由原生响应器更新，避免把指针几何变成整页的视图状态。
- 分离周日期区与时间线。坐标移动时复用未变化卡片的键盘／辅助功能树和时间网格；标题、状态、选择、拖动预览、日期／语言、数据版本仍参与更新。
- 用七天位掩码替换分行时的集合分配，第一条可用行的排序不变。300 条区间与原集合算法逐项对照通过。
- 日期区共享的是内容坐标，扣除系统表头的偏移约定差异，消除相邻周同步时反复回跳的反馈。

预期可见外观、原生顶部材质、回弹、日期定位、键盘及拖动规则相同。内部差异是屏幕外的未选中日期卡片按需创建；极快滚动时的实际感受和屏幕阅读器浏览屏幕外项目仍需人工确认。本轮没有把真实触控板惯性或辅助功能遍历列为已验收。

## 人工验收包

独立的 Release 100 条／1,000 条包位于 `dist/DayVDO-0.8.0-Performance-20261020-010613/`。各自的“打开性能测试版.command”会在首次打开时复制合成数据、设置周视图；再次打开保留该测试包的操作结果。支持目录和偏好均使用独立测试标识，不读取或覆盖正式数据。

先退出旧测试版，打开 100 条包：

1. 按 ⌘2 进入日历周视图，再按 ⌘1／⌘2 反复切换。观察内容和位置是否稳定，切换是否比之前顺畅。
2. 横向缓慢滚动、快速滑动、惯性中反向，连续跨过周边界。观察表头、日期卡片和时间线是否同步，是否出现空白或位置回跳。
3. 分别竖向滚动上方待办区和下方时间线，检查原生回弹和顶部半透明效果；在 1,000 条包重复此操作以放大压力。
4. 选中／编辑卡片、拖动到相邻周、调整安排、缩放时间线。确认选中状态、预览、保存结果与时间位置正确。

两个应用为本机 arm64、macOS 15 起、SDK 27 的临时签名测试构建；打包验证记录保存在包目录的“打包验证.json”。
